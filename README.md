# 画像最適化ツール

画像の圧縮・リサイズ・トリミング・連番リネームをブラウザ内でまとめて実行する単体ツール。ビルド不要・依存パッケージなしの素の HTML/JS で、選んだ画像はどこにも送信しない。

## 使い方

### 1. ローカルサーバー経由で開く（推奨）

フォルダへの直接書き出し（File System Access API）が使えるのはこの方法だけ。

```bash
cd tools/image-optimizer
python3 -m http.server 8080
# ブラウザで http://localhost:8080/ を開く
```

### 2. index.html を直接開く

`open tools/image-optimizer/index.html` でも動く。ただし `file://` ではフォルダ書き出しが使えないため、出力は ZIP ダウンロードになる。

### 3. Chrome 拡張として常駐させる

1. Chrome で `chrome://extensions` を開く
2. 「デベロッパーモード」をオンにする
3. 「パッケージ化されていない拡張機能を読み込む」で `tools/image-optimizer` を選ぶ
4. ツールバーのアイコンをクリックするとタブで開く

## 画面構成

左カラムに対象ファイルの一覧（選択・実行ボタン・進捗・結果）、右カラムに設定フォームを並べる。一覧を見ながら設定を触れるよう、左カラムはスクロールに追従する。ウィンドウ幅 900px 以下では 1 カラムに折り返す。

## 入力

- フォルダ選択（サブフォルダも再帰的に読み込む。`webkitdirectory` フォールバック時は常に再帰）
- ファイル選択（複数可）
- ドラッグ&ドロップ（フォルダ可）

読み込む拡張子: `jpg` `jpeg` `jfif` `png` `webp` `avif` `gif` `bmp` `ico` `svg` `tif` `tiff` `heic` `heif`

## 圧縮

出力形式は WebP / JPEG / PNG（ブラウザが対応していれば AVIF）から選ぶか、いちばん軽くなるものを自動で選ばせる。

| モード     | 挙動                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------- |
| 自動       | 元画像との SSIM が基準（既定 0.98）を満たす範囲で、いちばん軽くなる品質を二分探索で選ぶ   |
| 目標サイズ | 指定 KB に収まる最大品質を選ぶ。最低品質でも収まらなければ解像度を 15% ずつ落として再挑戦 |
| 品質指定   | スライダーの品質でそのままエンコードする                                                  |

「いちばん軽い形式を自動選択」では候補形式それぞれで上の探索を回し、最小のものを採用する。透過がある画像は WebP / PNG、無い画像は WebP / JPEG を候補にする。再エンコードしても軽くならない場合は元ファイルをそのまま出力する（既定でオン）。

## リサイズ・トリミング

- トリミング: なし / 正方形 / 比率指定（例 16:9）。切り出し位置は 9 方向から選ぶ
- リサイズ: なし / 比率(%) / 幅指定 / 高さ指定 / 枠に収める / 指定サイズにする
- 「元より大きくしない」をオンにすると、指定値が元画像より大きい場合は元サイズに抑える
- 縮小は 1/2 ずつ段階的に描画してから最終サイズに合わせる

比率トリミングと「指定サイズにする」を組み合わせると、はみ出しを切ったうえで指定サイズにぴったり合わせられる。

## 自動調整

既定はオフ。プリセットを選ぶか、スライダーを触って `カスタム` にする。1 枚目の画像で調整前後を並べたプレビューが出る。

| プリセット   | 中身                                                                               |
| ------------ | ---------------------------------------------------------------------------------- |
| 控えめ       | オートレベル（クリップ 0.1%）、彩度 +3%、シャープ 25%                              |
| 標準         | オートレベル、ホワイトバランス、彩度 +8%、シャープ 40%、トーン 15%                 |
| 強め         | オートレベル（クリップ 1%）、ホワイトバランス、彩度 +18%、シャープ 60%、トーン 35% |
| HDR 風トーン | オートレベル、ホワイトバランス、彩度 +12%、シャープ 35%、トーン 80%                |

- **オートレベル**: 輝度ヒストグラムの上下 n% を捨てて黒点・白点を伸ばす。階調の幅が 16 未満の平坦な画像は、ノイズを持ち上げるだけなので補正しない
- **ホワイトバランス**: 画像全体の平均を無彩色とみなして RGB ゲインを求める（グレーワールド）。意図的な色調を壊さないよう、ゲインは 0.8〜1.25 に収める
- **彩度**: 輝度を軸に色差を伸縮する
- **シャープ**: 輝度だけを見るアンシャープマスク（半径 1px）。色のにじみが出ない。リサイズ後にかかる
- **HDR 風トーン**: シャドウを持ち上げてハイライトを圧縮するトーンカーブ＋広い半径のアンシャープマスク。出力はあくまで SDR

調整はリサイズ・トリミングの後、品質探索の前に入る。SSIM の基準画像も調整後の絵で作るため、自動モードが「調整＝劣化」と誤判定して品質を上げ続けることはない。ただし HDR 風トーンは細部のコントラストが増えるぶん、同じ品質でも容量は増える（実測で +30% 程度）。

## リネーム

パターン例: `image-{連番}.{ext}` → `image-001.webp`

| トークン                      | 展開結果                                          |
| ----------------------------- | ------------------------------------------------- |
| `{連番}` / `{seq}` / `{n}`    | 連番。`{連番:4}` で桁数指定（既定はゼロ埋め設定） |
| `{名前}` / `{name}`           | 元のファイル名（拡張子なし）                      |
| `{ext}` / `{拡張子}`          | 出力形式の拡張子                                  |
| `{元拡張子}` / `{srcext}`     | 入力ファイルの拡張子                              |
| `{日付}` / `{date}`           | `20260908`。`{日付:YYYY-MM-DD}` で書式指定        |
| `{時刻}` / `{time}`           | `143005`。`{時刻:HH-mm}` で書式指定               |
| `{幅}` `{高さ}` / `{w}` `{h}` | 出力後のピクセル数                                |
| `{親フォルダ}` / `{parent}`   | 元ファイルの直上フォルダ名                        |

- 連番の順序は並び順（ファイル名・更新日時・サイズ）で決まる
- 同名になった場合は `-2`, `-3` を付けて衝突を避ける
- パターンに書いた拡張子と実際の出力形式が違う場合、既定では出力形式を優先する（`image-{連番}.png` で WebP 出力なら `.webp` になる）

## 設定プリセット

現在の設定に名前を付けて保存し、プルダウンから選び直すだけで戻せる。

- 保存対象: 圧縮・リサイズ・トリミング・自動調整・リネーム・出力先の各コントロール
- 保存されないもの: 選択中のファイルと出力フォルダ（フォルダへのアクセス権はページをまたいで保持されないため、実行のたびに選ぶ）
- 保存先はブラウザの localStorage（最大 50 件）。最後に使った設定は自動で控え、次回起動時に復元する
- プライベートモードなど localStorage が使えない環境では、この機能だけ無効になる（圧縮処理には影響しない）

## 出力

- フォルダに書き出す: 出力先を選ぶ。元のサブフォルダ構造を保つかどうかを選べる
- ZIP でまとめてダウンロード: 無圧縮 ZIP を 1 ファイル生成する

入力元と同じフォルダを出力先に選んだ場合は、上書きの確認を出す。

## 制限

- HEIC / HEIF / RAW はブラウザがデコードできないため失敗する（macOS のプレビューで JPEG に変換してから投入する）
- 再エンコードするため EXIF（撮影情報・位置情報）は残らない
- GIF は 1 コマ目のみを扱う（アニメーションは保持しない）
- Chrome は AVIF を書き出せない。起動時に判定し、書き出せる形式をヘッダーに表示する
- 本物の HDR 画像（PQ / HLG・ゲインマップ付き）は書き出せない。Chromium 141 で確認した範囲では、Canvas 2D の色空間は `srgb` と `display-p3` のみ（`rec2100-pq` / `rec2100-hlg` は例外）、`float16` は `unorm8` に落ち、`toBlob` は jpeg / png / webp しか通らない。対応するには libultrahdr などの WASM エンコーダが要る
- HDR 写真（Ultra HDR JPEG など）を入力しても、Canvas に描いた時点でゲインマップが落ちて SDR になる
- PNG は可逆圧縮のみ（減色による軽量化はしない）。写真を PNG で出すと容量が増えることがある

## テスト

寸法計算・リネーム・品質探索・自動調整・設定プリセット・ZIP 生成はブラウザ非依存なので、Node だけで検証できる（47 ケース）。

```bash
node tools/image-optimizer/test/run-tests.mjs
```
